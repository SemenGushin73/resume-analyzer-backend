code-style-guide


## ✅ Основные принципы

- Пиши **читаемо**, не для машины — для человека.
- Следуй принципам **Clean Architecture**:
    - Не смешивай домен с инфраструктурой
    - Вся бизнес-логика — только в domain и application слоях
- Не используй `public` поля
- Разделяй ответственность: один класс — одна задача

## 🧹 Code Style

- Java 21
- Именование классов: `PascalCase` (например, `UserService`)
- Именование переменных и методов: `camelCase` (`createUser`, `accountNumber`)
- Константы: `UPPER_CASE_WITH_UNDERSCORES`

## 🛡 Валидация

- Используй `@Valid`, `@NotNull`, `@Email`, и т.п. где это применимо
- Валидация в value object — обязательно (например, `Email`, `Money`)

## 🧪 Тесты

- Unit-тесты обязательны на сервисы и бизнес-логику
- Используем `JUnit 5` и `Mockito`
- Пиши осмысленные названия: `shouldCreateUserWhenEmailValid`

## 🔀 Git / MR

- Все изменения — через Merge Request
- Делай короткие ветки по названию задачи: `feature/user-registration`
- В коммите пиши: `[#123] Реализовал регистрацию`

## 📄 Дополнительно

- Оформляй JavaDoc хотя бы к публичным методам
- Не оставляй закомментированный код
- Прежде чем пушить — сделай `./gradlew build` локально

## 🔍 Что проверяет Checkstyle в проекте

Checkstyle — это инструмент статического анализа кода, который проверяет соблюдение стиля и базовых архитектурных правил. В проекте настроен `checkstyle.xml`, который включён в CI/CD (GitLab).

---

### 📋 Что именно проверяется:

| Категория                   | Правило                                  |
|-----------------------------|------------------------------------------|
| 📏 Форматирование строк     | Максимум 120 символов (`LineLength`)     |
| 🚫 Лишние пробелы           | `NoWhitespaceBefore`, `NoWhitespaceAfter`|
| 🧱 Отступы и табуляция       | Проверяется 4 пробела (`Indentation`)    |
| 🔲 Пустые строки             | Между методами и классами (`EmptyLineSeparator`) |
| 🧩 Порядок модификаторов     | `public static final`, а не вразнобой     |
| 🔄 Использование final      | Локальные неизменяемые переменные должны быть `final` |
| ❗ Стиль блоков              | Требуются фигурные скобки (`NeedBraces`) |
| 🚫 Пустые блоки              | `EmptyBlock` запрещает `{}` без комментария |
| ❓ Тернарные операторы       | `AvoidInlineConditionals` — не злоупотреблять |
| 🔍 equals/hashCode          | Если переопределяешь один — пиши оба     |

---

### 🛠 Как выполнить проверку локально

```bash
./gradlew checkstyleMain checkstyleTest
```

HTML-отчёт находится в `build/reports/checkstyle/`

---

### ✅ Что стараться соблюдать

- Использовать 4 пробела, не табы
- Не писать слишком длинные методы (>50 строк)
- Добавлять пустую строку между методами
- Держать порядок импортов и модификаторов
- Не оставлять пустых блоков и не злоупотреблять тернарными условиями
- Следовать JavaDoc-оформлению классов и публичных методов
